# Madina Electronics Manager Bot

A production-oriented Telegram inventory, sales, expense, and customer-credit
manager backed by the existing Google spreadsheet. It is designed for a
non-technical shop manager: every action is guided by buttons, validated, and
shown for confirmation before it changes business data.

## Complete manager features

- Full inventory browsing with **Previous** and **Next** pagination; no matches
  are silently cut off after 10 items
- Search by SKU, brand, category, model, variant, or color
- Add a new product with automatically generated SKU, opening stock, cost,
  selling price, color, and an individual low-stock level
- Receive stock with purchase cost and supplier/invoice reference
- Remove damaged, corrected, or supplier-returned stock with a required reason
- Record cash, bank, and named customer-credit sales
- Record customer returns and refunds while restoring stock
- Persist cost and selling prices, including for older sheets without price columns
- Record operating expenses
- Track customer credit balances and received payments
- Daily sales, COGS, gross-profit, expense, refund, payment, and stock-movement report
- Inventory quantity, cost-value, retail-value, missing-price, low-stock, and
  out-of-stock report
- Paginated transaction history with unique references and Telegram operator identity
- Optional multi-user allowlist for the owner and family/staff accounts

## Data safety

- Quantity is re-read directly from Google Sheets immediately before every write,
  preventing a cached screen from allowing an oversale.
- Stock writes are serialized inside the running process.
- If audit logging fails after a quantity change, the bot attempts to roll the
  quantity back to its original value.
- Stale Telegram confirmations are discarded during a redeploy.
- User-entered text is written as raw sheet data, not evaluated as a spreadsheet formula.
- Manager-owned data uses separate `Manager_Inventory`, `Manager_Catalog`, and
  `Manager_Transactions` worksheets. Existing `Transactions` data from older
  releases is preserved and not mixed with the new schema.

Run exactly **one Railway replica**. Telegram long polling and the write lock are
designed for a single active bot process.

## Required Railway variables

| Variable | Value |
|---|---|
| `TELEGRAM_BOT_TOKEN` | Complete token generated by BotFather |
| `GOOGLE_SHEET_ID` | ID between `/d/` and `/edit` in the spreadsheet URL |
| `GOOGLE_CREDENTIALS_JSON` | Complete Google service-account JSON |
| `AUTHORIZED_USER_IDS` | Recommended comma-separated Telegram IDs, such as `123456789,987654321` |
| `LOW_STOCK_THRESHOLD` | Optional default for products without their own level; defaults to `3` |
| `PAGE_SIZE` | Optional products/records per Telegram page; defaults to `8`, constrained to 5–12 |

Share the spreadsheet with the service account's `client_email` as **Editor**.

To authorize another person, ask them to open the bot and send `/id`, then add
their numeric ID to the same comma-separated `AUTHORIZED_USER_IDS` value and
redeploy. If the variable is empty, anyone who finds the bot can operate it.

## Existing inventory-sheet format

The bot scans the first 15 rows of every non-manager worksheet for a recognizable
header. A quantity column plus at least one product-description column is required.

Recommended columns:

| SKU | Brand | Category | Model | Variant | Color | Qty | Cost Price | Sale Price | Low Stock Level |
|---|---|---|---|---|---|---:|---:|---:|---:|
| PEL-21850-S | PEL | Refrigerator | PRGD 21850 | Glass Door | Silver | 4 | 135000 | 149000 | 2 |

Common alternatives are accepted, including `Company` for Brand, `Quantity` or
`Stock` for Qty, `Colour` for Color, `Purchase Price` for Cost Price, and
`Selling Price` for Sale Price. Prices and low-stock levels set in Telegram are
stored in `Manager_Catalog`, so old worksheets do not need to be redesigned.

Do not rename or manually reorder columns in worksheets whose names begin with
`Manager_`. The bot validates their headers and stops safely instead of writing
into an unexpected layout.

## Deployment

1. Connect this repository to a Railway service.
2. Keep the service at one replica.
3. Add all required variables above.
4. Ensure the Google Sheet is shared with the service account as Editor.
5. Deploy. The included Procfile starts `python bot.py`.
6. In Telegram, send `/start`, press **Refresh**, and verify the loaded product count.
7. Test an addition, sale, return, and expense using non-critical sample data.

## Commands

- `/start` or `/menu` — open the manager menu
- `/refresh` — reload inventory from Google Sheets
- `/cancel` — cancel the current workflow
- `/id` — show the sender's Telegram user ID

Typing a product name from the main menu also starts a stock search.

## Files

- `bot.py` — Telegram menus, pagination, guided workflows, and confirmations
- `storage.py` — Google Sheets adapter, validation, inventory rules, accounting,
  transaction audit, and rollback logic
- `requirements.txt` — pinned Python dependencies
- `Procfile` — Railway worker start command

## Security

- Never commit Telegram tokens or Google credentials to GitHub.
- Configure `AUTHORIZED_USER_IDS` before real use.
- If a bot token is exposed in a message or log, revoke it through BotFather and
  replace the Railway variable.
- Back up the Google spreadsheet regularly; it remains the system of record.
